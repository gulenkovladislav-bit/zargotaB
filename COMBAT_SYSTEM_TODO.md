# Боевая система Зарготы — главный рабочий TODO

## Назначение

Бой должен помогать мастеру вести историю, а не превращать игру в жёсткий
компьютерный симулятор. Система автоматизирует повторяемое и опасное для
синхронизации: очередь, ресурсы действий, броски, HP, статусы, журнал и защиту
от повторного применения. Смысл необычного действия, допустимость и итог всегда
может определить мастер.

Главный принцип интерфейса:

> Игрок формулирует намерение, система собирает известный контекст, мастер
> получает одну понятную карточку и решает, как и когда её разыграть.

- [x] Экономика хода: `long`, `short`, `reaction`, `movement`, `movementMax`.

- [x] Идемпотентные operation ID для основных боевых бросков и урона.
- [x] Ручная борьба за жизнь при 0 HP.

Наличие пункта здесь не означает, что его интерфейс уже полностью удобен или
проверен живым прогоном. Живой ГМ + игрок остаётся обязательной проверкой.

## Граница автоматизации

### Автоматизируем уверенно

- проверку доступного долго/короткого действия, реакции и движения;
- известную дистанцию, цель, оружие, предмет, формулу и активные состояния;
- бросок кубиков и показ результата после анимации;
- HP, временные HP, заряды, стаки и журнал после подтверждения;
- защиту от двойного клика, повторного Firebase-снимка и переподключения;
- напоминания мастеру о потенциально сработавшем условии;
- восстановление незавершённой заявки после перезагрузки.

### Не решаем за мастера

- возможно ли нестандартное действие в текущей сцене;
- достаточно ли описанного условия для срабатывания;
- какую проверку, сложность, цену или последствие назначить;
- кого затронуло импровизированное действие;
- должна ли заявка сработать сейчас, остаться висеть или пропасть;
- трактовку свободного текста заклинаний, особенностей и предметов.

Автоматический триггер по умолчанию только подсвечивает карточку. Он не тратит
реакцию, предмет или HP без явного решения мастера.

## Единое намерение игрока

Новые механики должны расширять существующий `actionRequest`, а не создавать
параллельные несовместимые ветки Firebase. Минимальная совместимая форма:

```js
{
  id: "stable-operation-id",
  actionKind: "combat-intent",
  status: "pending",
  stage: "submitted",
  details: {
    cost: "short",
    intentKind: "improvised",
    text: "Подсекаю цепь люстры, когда враг окажется под ней",
    targetKeys: ["token:..."],
    weaponId: "...",
    itemId: "...",
    abilityId: "...",
    trigger: null,
    suggestedResolution: "check"
  }
}
```

Неизвестные поля игнорируются старыми клиентами. Читаемая `text` остаётся
обязательной страховкой и основой журнала.

## Типы действий

### 1. Долгое действие

- [x] Базовая атака использует существующую двухфазную машину.
- [ ] Заклинания и навыки ведут в общий конструктор намерения.
- [ ] Помощь, уклонение, стабилизация и оценка врага получают карточку мастера.
- [ ] Нестандартное долгое действие можно заявить свободным текстом.
- [ ] Ресурс списывается только при принятии/начале разыгрывания мастером.
- [ ] Отказ не тратит ресурс; отмена после начала требует решения мастера.

### 2. Короткое действие — приоритетный блок

Короткое действие не должно быть набором жёстких автоматических кнопок.
Игрок выбирает известный вариант либо «Другое» и отправляет заявку.

- [x] Единая кнопка открывает компактный конструктор короткого действия.
- [x] Быстрые варианты: толчок, захват, разоружение, сбить с ног, достать или
  передать предмет, выпить/применить предмет, быстрый навык, взаимодействие с
  объектом, анализ, другое.
- [ ] Карточка автоматически показывает цель, дистанцию, доступный ресурс,
  предмет/навык и мешающие состояния.
- [x] Мастер выбирает: `Разрешить без броска`, обычную проверку,
  встречную проверку, спасбросок цели или `Отклонить`. Редактирование исходного
  условия остаётся отдельным следующим шагом.
- [x] После одобрения атомарно списывается ровно одно короткое действие.
- [x] Повторное Firebase-событие не может списать действие второй раз.
- [x] Первый контур не применяет перемещение, статус, урон или предмет скрыто;
  такие результаты остаются отдельным ручным решением мастера.
- [ ] Если действие создаёт перемещение, статус или урон, мастер получает
  отдельный подтверждаемый результат, а не скрытое автоматическое изменение.
- [x] Пока заявка ожидает решения, кнопка игрока показывает «Заявка отправлена».
- [x] Игрок видит постоянный статус: отправлено → нужен бросок → ГМ решает →
  принято/закрыто без эффекта.

### 3. Передвижение

- [x] Линия дистанции зависит от размера клетки.
- [x] Игрок может отправить план вне дистанции с предупреждением мастеру.
- [ ] Нулевой остаток движения блокирует новую заявку и не повторяет старую
  анимацию.
- [ ] Частичное движение до и после действия сохраняет один общий остаток.
- [ ] Перемещение, вызванное толчком, телепортацией или мастером, не расходует
  обычный запас без явного флага.
- [ ] Реакции на выход из ближней дистанции только предлагаются мастеру.
- [ ] Живой тест плавности на двух клиентах при нескольких жетонах и статусах.

### 4. Бесплатное действие / План Б

- [ ] Свободная реплика, мелкое взаимодействие и свободный бросок не тратят
  долгое или короткое действие.
- [ ] Мастер может одним кликом повысить цену заявки до `short` или `long`.
- [ ] Несколько бесплатных заявок не должны забивать основной список: свёртка
  по игроку и мягкий антиспам без запрета импровизации.

### 5. Обычная реакция

Реакция начинается не с автоматического скрипта, а с запроса мастера.

- [ ] Мастер выбирает событие/цель и видит подходящих участников с доступной
  реакцией.
- [ ] Отправляет одному или нескольким игрокам короткий запрос: «Реагировать?».
- [ ] Игрок видит `Принять`, `Пропустить` и при необходимости выбор оружия,
  предмета или способности.
- [ ] Ответ остаётся видимым мастеру, пока он не исполнит или не закроет его.
- [ ] Реакция списывается при исполнении, а не при показе запроса.
- [ ] Можно оставить решение ручным, назначить бросок или открыть существующую
  машину атаки.
- [ ] Опциональный таймер является только подсказкой; по умолчанию заявка не
  исчезает сама.

### 6. Подготовленное действие игрока

- [x] Игрок задаёт условие, действие, цель, оружие/предмет и уточнение.
- [x] Мастер подтверждает подготовку; тогда расходуется долгое действие.
- [x] Подготовка висит отдельной закреплённой карточкой, а не теряется в логе.
- [ ] При похожем событии карточка подсвечивается как «возможно сработало».
- [ ] Мастер выбирает `Исполнить`, `Спросить игрока`, `Оставить`, `Отменить`;
  исполнение, сохранение и отмена готовы, отдельный запрос игроку ещё нет.
- [x] При исполнении расходуется реакция; открытие заполненного инструмента
  атаки или предмета остаётся следующим блоком.
- [x] Если реакция уже потрачена, карточка остаётся с понятной причиной.
- [x] Условие может переноситься между ходами до отмены, срабатывания или
  указанного мастером срока.

### 7. Отложенное действие или событие мастера

Это не реакция персонажа и не должно храниться в `preparedReaction`.

- [ ] Очередь мастера: раунд, позиция хода, условие, текст, связанные жетоны.
- [ ] Варианты: начало/конец хода, начало раунда, через N раундов, ручной
  сигнал, HP ниже порога, вход в область, особое условие.
- [ ] Система только напоминает; мастер нажимает `Разыграть сейчас`.
- [ ] Можно перенести на следующий ход, приостановить или отменить.
- [ ] После срабатывания создаётся журнал с operation ID.
- [ ] Повторное подключение восстанавливает очередь без повторного эффекта.

### 8. Предметы и раздел «Товары»

- [ ] Игрок выбирает реальный `itemId`, количество/заряд и цель.
- [ ] Заявка показывает описание товара, но не трактует свободный текст как
  гарантированный механический эффект.
- [ ] Мастер выбирает ручной эффект, проверку, лечение, урон, статус или
  открывает другой инструмент.
- [ ] Применение эффекта и расход предмета — два связанных этапа одной операции.
- [ ] Предмет списывается только после подтверждённого применения.
- [ ] Повтор операции безопасен; офлайн-запись проходит через существующий
  mutation/outbox, а не прямую перезапись инвентаря.
- [ ] Возврат ошибочно списанного предмета доступен мастеру и попадает в журнал.

### 9. Заклинания, навыки и существа

- [ ] Каталог нормализует только явно известные поля: цена действия, дальность,
  формула, цель, спасбросок, статус, кулдаун и заряды.
- [ ] Расплывчатое описание автоматически помечается `Решает мастер`.
- [ ] Мастер может сохранить принятое толкование как шаблон, не меняя исходный
  текст способности.
- [ ] Способности существ используют тот же контракт действий и статусов, а не
  отдельную боевую машину.
- [ ] Специальная анимация является оформлением результата и никогда сама не
  применяет урон или состояние.

## Пульт мастера: очередь решений

- [ ] Один центр входящих намерений вместо нескольких конкурирующих окон.
- [ ] Вкладки: `Сейчас`, `Реакции`, `Подготовлено`, `Отложено`, `Завершено`.
- [ ] Приоритетные карточки закрепляются и не моргают при Firebase-снимках.
- [ ] Карточка показывает автора, цену действия, цель, дистанцию, источник,
  условие, потенциальные конфликты и время ожидания.
- [ ] Быстрые решения: без броска, проверка, встречная проверка, спасбросок,
  атака, ручное применение, изменить, отложить, отклонить.
- [ ] Мастер может дописать условие или цену, не уничтожая исходную заявку.
- [ ] Фильтр по текущему ходу и предупреждение о заявках прошлого раунда.
- [ ] Свёрнутая перемещаемая панель показывает количество ожидающих решений.

## Машина состояния намерения

Базовые стадии:

```text
draft → submitted → pending-gm → approved
      → waiting-roll → resolving → applied → logged
      ↘ rejected / cancelled / expired
```

- [ ] Каждая стадия имеет `stageTimes` и стабильный `operationId`.
- [ ] Переходы валидируются; старый снимок не возвращает заявку назад.
- [ ] `applied` означает, что механическое изменение совершено ровно один раз.
- [ ] `logged` можно повторить без повторного урона, расхода или статуса.
- [ ] Ошибка оставляет карточку восстанавливаемой, а не молча закрывает её.
- [ ] Ручная заявка может завершиться без механического изменения.

## Визуальная и звуковая последовательность

- [x] Попадание и урон разделены двумя бросками.
- [x] HP и кровь не должны меняться до завершения кубика урона.
- [ ] Один источник управляет звуком и анимацией каждого operation ID.
- [ ] Попадание показывает результат, но не проигрывает преждевременный импакт.
- [ ] Урон: кубик завершён → снаряд/удар → реакция цели → HP/статус → журнал.
- [ ] Промах: кубик завершён → уклонение/пролёт → один звук → журнал.
- [ ] Крит не дублирует обычный удар поверх специального эффекта.
- [ ] Настройка сниженных эффектов сохраняет порядок событий.

## Раунды, статусы и окончание хода

- [ ] Тики начала/конца хода показываются мастеру до автоматического применения,
  если формулировка статуса неоднозначна.
- [ ] Однозначные DoT/регенерация можно включить в автоматический режим отдельно.
- [ ] Нельзя завершить ход с незавершённым обязательным броском урона.
- [ ] Подготовленные и отложенные карточки проверяются перед сменой хода.
- [ ] Реакция восстанавливается в установленный правилами момент один раз.
- [ ] Конец боя не удаляет незаписанные решения и позволяет сформировать итог.

## Журнал и восстановление

- [ ] В журнале видны исходная заявка, правка мастера, броски и итог.
- [ ] Игрок видит разрешённую часть решения; скрытые параметры остаются у ГМа.
- [ ] По operation ID можно понять, применён ли эффект после переподключения.
- [ ] ГМ может отменить последний механический результат отдельной компенсирующей
  операцией; история не переписывается задним числом.
- [ ] Незавершённые карточки восстанавливаются после обновления обоих клиентов.

## Обязательные сценарии двух клиентов

- [ ] Игрок заявляет короткий толчок; ГМ назначает встречную проверку.
- [ ] Игрок готовит дальнюю атаку; условие срабатывает через два чужих хода.
- [ ] ГМ запрашивает реакцию у двух игроков; реагирует только один.
- [ ] Отложенное событие переносится на следующий раунд и срабатывает один раз.
- [ ] Игрок заявляет товар; эффект применён, количество списано один раз.
- [ ] Нестандартная заявка решается мастером без механического эффекта.
- [ ] Один клиент перезагружается на каждой промежуточной стадии.
- [ ] Повтор Firebase-снимка не дублирует звук, анимацию, HP, статус или расход.
