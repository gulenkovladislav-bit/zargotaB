## Стабильная временная линия

`разрешение → dice animation → reveal результата → hit/miss/crit FX → отдельный damage dice → завершение presentation → HP/status transaction → token reaction → один semantic sound → log`

Для действий без кубика используется та же модель без пустой паузы:

`подтверждение → cast/action telegraph → effect → state transaction → reaction/sound → log`

Каждая стадия обязана иметь либо видимую индикацию, либо немедленный переход; «нажал и пусто» считается ошибкой.

6. External damage and movement: GM panel damage/heal/status/move during and outside combat.
7. Stress: repeated Firebase snapshots, motion coalescing, one RAF per surface, reduced motion.

Живой GM-сценарий движения NPC выявил ещё два дефекта границы завершения. Firebase уже хранил точку назначения, но мастерский редакторский `draft` сохранял старые координаты и следующий `renderTokens()` возвращал NPC назад; кроме того, класс ходьбы мог сниматься на ненулевой фазе наклона. Авторитетный `lastMovement` теперь синхронизирует только подтверждённую координату конкретного токена в локальный draft (с проверкой, что сцена действительно находится в `toX/toY`), а амплитуда шага плавно затухает до нуля на последних 14% пути. Это не добавляет таймеров, Firebase-записей или новых форматов данных.

Повторный GM-аудит основных кликов обнаружил функциональный разрыв, который не покрывали playback-тесты: подсказка пульта требовала «кликните по жетону», но `renderTokens()` намеренно оставлял клик без открытия, а карточки существ в инициативе не имели обработчика. Оба входа снова ведут в один существующий `zgGmInterventionOpenToken(..., 'entity')`. Открытие защищено от ложного срабатывания после drag, Shift-выделения, выбора цели атаки, движения и предпросмотра глазами игроков; заблокированный NPC остаётся доступен для просмотра.

Повторная сверка интерфейса атаки выявила ещё один неполный перенос: разметка `.zg-combat-attack-main`, раскрываемых настроек броска, предупреждений и подтверждения игрока присутствовала, но соответствующие CSS-селекторы из a7cc отсутствовали. Поэтому браузер показывал нативный select поверх имени атакующего и крупный неоформленный summary. Точечно восстановлены только совпадающие с текущей разметкой селекторы: attack main/advanced/warning, request feedback, prepared actions, широкое окно выбора участников и target-aware player confirmation. Логика, Firebase, аудио и ассеты не переносились. Добавлен `combat-attack-ui-style.test.js`, который связывает разметку с обязательными стилями и мобильным/reduced-motion контрактом.
