# Заргота — ручная проверка плавности боя и VFX

Этот чек-лист проходится после изменений боя, движения, кубиков, звука, статусов, Firebase-синхронизации или визуальных presets. Он не заменяет автоматические тесты: сначала должны пройти `tests/*.test.js` и `git diff --check`.

## 1. Подготовка

- [ ] Для быстрого визуального smoke-теста открыть `index.html?qa_scene=1` → «Тест бросков» → «Настройка сцены» → `QA бой` → `QA активный`. Этот режим локальный и не пишет в Firebase.
- [ ] Использовать Firebase Auth + Database Emulator, а не рабочую комнату.
- [ ] Открыть два независимых клиента: ГМ через `127.0.0.1`, игрока через `localhost`.
- [ ] Проверить минимум два размера окна: широкий desktop и узкий/mobile.
- [ ] На одном клиенте оставить обычное качество, на другом включить минимальные эффекты или `prefers-reduced-motion`.
- [ ] В сцене должны быть герой, ближний NPC, дальний NPC и 3–6 дополнительных жетонов.
- [ ] До начала записать diagnostics: активные VFX, частицы, projectiles, RAF, pending cues, dice previews и число DOM-узлов.

## 2. Быстрый smoke-тест — 15–20 минут

### Движение

- [ ] Переместить героя на 2–3 клетки. Жетон идёт плавно через `translate3d`, не телепортируется в начало или конец.
- [ ] Пока жетон движется, отправить следующую точку. Новый путь начинается с текущей видимой позиции без скачка.
- [ ] Быстро отправить три последовательных movement snapshots одному жетону. Активен только один movement RAF.
- [ ] Одновременно переместить другой жетон. Первый корректно завершается, второй начинает путь со своей authoritative позиции.
- [ ] Во время движения изменить zoom/размер окна. Жетон и след остаются привязаны к scene-space цели.
- [ ] После завершения позиции ГМ и игрока совпадают в нормализованных `left/top`.

### Обычная атака

- [ ] Игрок отправляет заявку, ГМ одобряет, игрок физически перетаскивает d20.
- [ ] Один жест создаёт один запрос; повторный `pointerup` или быстрый двойной ввод не создаёт второй бросок.
- [ ] До окончания d20 не видны `ПОПАДАНИЕ`, `ПРОМАХ`, `КРИТ`, урон или реакция цели.
- [ ] При попадании сначала показывается результат атаки, затем отдельно появляется приглашение бросить урон.
- [ ] До окончания кубиков урона HP, временные HP, кровь и состояние «сражён» не меняются визуально.
- [ ] После `revealAt`: один impact, одна надпись урона, одна реакция жетона, один звук и одна запись лога.

### Варианты результата

- [ ] Промах: нет damage-roll, damage sound, крови и рукопашного FX поверх ranged projectile.
- [ ] Крит: один усиленный impact, удвоенные кубы по правилам, один итоговый commit.
- [ ] Полное поглощение временными HP: виден щит, обычная кровь не появляется.
- [ ] Дальняя атака: projectile заканчивается у цели; дополнительный melee slash не запускается.
- [ ] Скрытый результат NPC: игрок не узнаёт число или исход через label, траекторию либо звук раньше разрешённого момента.

### Ручные действия ГМ

- [ ] Урон из пульта: HP меняется после ACK/reveal, эффект и звук воспроизводятся один раз на обоих клиентах.
- [ ] Лечение и временные HP: используются support FX и один корректный звук, без hit reaction.
- [ ] Добавление/снятие статуса: значок, поверхность жетона, звук и лог не дублируются.
- [ ] Травма и снятие травмы не оставляют зависшие частицы или классы на жетоне.
- [ ] Режим «Только мне · тест»: эффект виден только ГМ, игрок получает 0 FX, Firebase event и HP не меняются.
- [ ] Режим «Всем игрокам»: оба клиента получают одну семантически одинаковую анимацию.

### Заклинания, экономика действий и реакции

- [ ] Атакующее заклинание: d20 заканчивается до hit/miss, HP и статусы остаются прежними до `revealAt`.
- [ ] Заклинание урона/лечения без d20: cast-пауза завершается до одновременного показа HP, статуса и итоговой надписи.
- [ ] Utility-заклинание без урона всегда заканчивается сообщением «эффект применён», отклонением или явной ошибкой.
- [ ] Призыв: игрок выбирает точку, ГМ подтверждает, на обоих клиентах появляется ровно один жетон `Призыв · …` в одинаковых координатах.
- [ ] ГМ связывает призванный жетон с Бестиарием/НПС; уже показанная сцена и остальные жетоны не заменяются.
- [ ] В локальном `QA активный` выбрать жетон `QA призыв · …`: кнопка `⚔ В конец очереди` видна, не переполняет панель и блокируется на время запроса.
- [ ] В двух вкладках ГМ одновременно нажать `⚔ В конец очереди` для одного жетона: участник появляется один раз, второй клиент получает понятный отказ.
- [ ] Завершить бой одновременно с запоздалым добавлением: `combat` не восстанавливается частично; следующий новый бой запускается нормально.
- [ ] Короткое и свободное действие дают видимый toast/event; повторный быстрый клик не расходует действие дважды.
- [ ] Подготовка расходует одно долгое действие и остаётся видимой до триггера.
- [ ] Срабатывание подготовленного действия расходует одну реакцию, очищает ожидание и показывает один итог.
- [ ] Остановка концентрации сохраняет название заклинания в сообщении и снимает только эффекты своего `sourceId`.
- [ ] Отмена выбора цели, Esc, неверная дальность, отклонение ГМ и потеря связи всегда снимают busy/targeting-состояние или дают понятный путь повтора.

## 3. Кубики и временная линия — 10–15 минут

- [ ] Одиночные d4, d6, d8, d10, d12 и d20 завершаются без зависшего preview ticker.
- [ ] Advantage/disadvantage показывает оба кубика, но использует один выбранный результат.
- [ ] Бросок 4–8 кубиков использует один общий ticker, не один таймер на кубик.
- [ ] Инициатива: карточки и результат появляются после броска, порядок одинаков у ГМ и игрока.
- [ ] Спасбросок: снятие статуса и cleanse FX происходят только после результата.
- [ ] Монета борьбы за жизнь: итог не виден до конца вращения; счётчики успехов/провалов обновляются в commit.
- [ ] Повторный Firebase snapshot с тем же eventId не повторяет звук, label, hit FX или лог.

## 4. Reconnect и плохая сеть — 10 минут

- [ ] Отключить сеть во время movement. RAF и trail прекращаются, жетон остаётся в последней видимой позиции без скачка.
- [ ] Отключить сеть во время projectile/impact. Canvas, pending cues, dice preview и временные DOM-узлы очищаются.
- [ ] Вернуть сеть. Старые FX не проигрываются пачкой и старые звуки не повторяются.
- [ ] Актуальные HP, статусы и позиции сходятся с Firebase snapshot после reconnect.
- [ ] Перейти в другую комнату во время активного FX. Эффект старой комнаты не переносится.
- [ ] Свернуть вкладку на 10–20 секунд и вернуть. Устаревшая косметика отбрасывается, состояние догоняется сразу.

## 5. Разные клиенты и режимы качества

- [ ] Desktop + mobile: actor, target и направление projectile семантически совпадают.
- [ ] Разный DPR/zoom: projectile заканчивается на той же scene-space цели.
- [ ] `dynamic`: разрешена короткая реакция жетона, логическая позиция не меняется.
- [ ] `anchored`: жетон неподвижен, impact визуализируется вокруг него.
- [ ] `minimal`: остаётся читаемый главный силуэт и label, тяжёлые частицы/trails отсутствуют.
- [ ] `prefers-reduced-motion`: нет дрожания, длительных перелётов и бесконечных decorative-анимаций.
- [ ] При неизвестном preset новый клиент использует family fallback, а бой не блокируется.

## 6. Производительность — 15–20 минут

### Нормальная нагрузка

- [ ] Запустить движение, 2 projectiles, 3 impacts, status tick и GM FX в течение 10 секунд.
- [ ] После завершения: `activeVfx=0`, `activeParticles=0`, `activeProjectiles=0`, `activeRafLoops=0`, pending cues `0`.
- [ ] DOM node count возвращается к исходному значению с допустимым постоянным Canvas root.
- [ ] Firebase snapshots не пересоздают token layer или тяжёлые scene DOM-узлы без структурного изменения.
- [ ] Нет повторных загрузок одного audio-файла или отсутствующего portrait на каждом render.

### Слабое устройство / CPU slowdown

- [ ] Повторить нагрузку при 4× CPU slowdown.
- [ ] Управление, кнопки и drag остаются отзывчивыми; Firebase callbacks не блокируются длинным draw.
- [ ] Adaptive quality сначала убирает trails/частицы, не главный impact и не result label.
- [ ] В low mode допустимы 30 FPS косметики, но нет зависшего RAF после завершения.
- [ ] Зафиксировать `maxFrameMs`, `frameOver20`, `frameOver34`, quality changes и причину downgrade.

## 7. Звук

- [ ] Попадание до damage-roll не воспроизводит звук нанесённого урона.
- [ ] Impact урона воспроизводит ровно один semantic sound cue.
- [ ] Ranged attack не добавляет звук рукопашного удара.
- [ ] Heal, cleanse, block, status, turn и round используют свои существующие маршруты.
- [ ] Локальный preview со звуком не слышен на втором клиенте.
- [ ] После reconnect или повторного snapshot старый звук не воспроизводится снова.
- [ ] Новые звуки имеют запись provenance в `audio/vtt-actions/SOURCES.md`; reserve-файлы не используются как боевые без отдельного решения.

## 8. Критерии приёмки

Изменение можно считать готовым, если:

- [ ] автоматические тесты и `git diff --check` проходят;
- [ ] ни один результат не показан раньше `revealAt`;
- [ ] на eventId приходится не больше одного sound, label, hit FX и commit;
- [ ] ГМ и игрок сходятся по результату, HP, статусам и scene-space позиции;
- [ ] после FX нет активных RAF, handles, particles, projectiles или временных DOM-узлов;
- [ ] minimal/reduced-motion остаётся читаемым и не меняет бизнес-логику;
- [ ] новые поля Firebase только добавочные, существующие форматы продолжают работать.

## Рекомендуемый порядок

1. Smoke-тест — после каждого небольшого изменения, 15–20 минут.
2. Кубики + reconnect — после изменения timeline/scheduler, ещё 20–25 минут.
3. Полный visual/performance прогон — перед объединением крупной волны FX, около 60–90 минут.
