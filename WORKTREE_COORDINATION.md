# Zargota: координация параллельных задач

Этот файл защищает проект от частичного переноса изменений между задачами Codex.
Задача, чат, Git-ветка и Git-worktree — не одно и то же. Новый worktree получает
только зафиксированный Git-снимок. Незакоммиченные и неотслеживаемые файлы из
другого worktree автоматически в него не попадают.

## Текущее распределение

Снимок на 2026-08-09. Перед использованием всегда запускать динамический аудит.

Ветка предметов и визуалов должна быть заново найдена через `git worktree list`:
ранее использовавшийся worktree `9b0c` сейчас не зарегистрирован в этом Git-репозитории.
Нельзя считать его содержимое частью `main` или любой другой задачи без проверки.

## Обязательная проверка перед новой задачей

Из любого worktree проекта:

```sh
zsh scripts/audit-worktrees.sh
zsh scripts/audit-worktrees.sh --source /абсолютный/путь/к/исходному/worktree
```

До редактирования должны быть явно записаны:

```text
source_worktree: абсолютный путь
source_head: полный Git commit
source_branch: имя ветки или detached
source_dirty_files: число
transfer_mode: commit | explicit-file-list | patch-bundle
included_paths: что переносится
excluded_paths: что намеренно не переносится
validation: какие тесты и двухклиентный сценарий нужны
```

Если `source_dirty_files` больше нуля, создание нового worktree от `source_head`
не является переносом текущей работы. Сначала нужен один из трёх явных способов:

1. Разрешённый пользователем checkpoint-коммит — самый надёжный вариант.
2. Согласованный список файлов и точечный перенос с последующим сравнением diff.
3. Patch-bundle плюс отдельный список неотслеживаемых и бинарных файлов.

`git stash`, копирование всего `index.html` или всей папки и перенос «по памяти»
не считаются безопасным handoff: они скрывают границы изменений и могут смешать
аудио, предметы, Firebase, Bestiary и боевую логику.

## Правила параллельной работы

- У каждого направления один явно названный авторитетный worktree.
- Новая задача сначала читает этот реестр и запускает аудит, затем сравнивает diff.
- Для пересекающихся файлов (`index.html`, `zargota-network.js`, Firebase rules)
  перенос выполняется по смысловым блокам, а не заменой целого файла.
- Звуки запускаются только от подтверждённого семантического перехода состояния;
  визуальный render и Firebase snapshot сами по себе не являются новым событием.
- После каждого переноса фиксируются исходный HEAD, список файлов и результаты тестов.
- Коммиты, push, reset и удаление не выполняются без прямого разрешения пользователя.

## Что произошло между `a7cc` и `16e8`

`16e8` находится на 18 коммитов впереди `f82fe5d7`, но незакоммиченный слой
worktree `a7cc` в эти коммиты не входил. Поэтому часть боевого UI, иконки и
изображения времени остались физически в `a7cc`; Git их не удалял. Ошибка была
в выборе источника handoff: использовался commit, а не полный diff живой задачи.
