## 1. Цель

Довести каноническую сумку героя и связанные с ней системы до одного
согласованного поведения в локальном листе, Firebase-комнате, свободном
исследовании и бою:

- клик по герою открывает каноническую сумку, а не старый параллельный лист;
- текст и числа читаются на полном экране без увеличения всей внешней рамки;
- статусы берутся из Мануала, не дублируются и имеют правильное описание;
- ГМ задаёт длительность статуса в раундах, часах или днях;
- статус влияет на бой и получает оптимизированный визуальный эффект на жетоне;
- время приключения становится авторитетным состоянием комнаты;
- журнал получает светлую бумагу, изображения заданий и отдельный фильтр;
- игрок может надёжно экипировать оружие в активной сессии;
- модель оружия поддерживает обе руки и двуручное оружие.

## 4. Целевые контракты данных

### 4.1. Канонический статус

Каждый активный статус должен иметь один стабильный `effectId` и один
`statusKey` из Мануала:

```js
{
  effectId: "status-...",
  type: "status",
  statusKey: "burn",
  label: "Горит",
  sourceId: "gm-manual:burn",
  sourceActorKey: "",
  stacks: 1,
  visibility: "public",
  durationUnit: "rounds", // rounds | hours | days | manual
  durationValue: 2,
  remainingRounds: 2,
  expiresAtWorldMinute: null,
  appliedAtWorldMinute: 0,
  appliedAtRound: 1,
  mechanicsVersion: 1
}
```

- [ ] Раундовые статусы используют только `remainingRounds`.
- [ ] Часовые и дневные статусы используют `expiresAtWorldMinute`.
- [ ] `manual` не уменьшается автоматически.
- [ ] Старые `unit`, `duration`, `remaining` читаются как fallback.
- [ ] `minutes` читаются при миграции, но новый GM-интерфейс по текущему запросу
  предлагает только раунды, часы и дни.
- [ ] Описание, иконка, цвет, save, модификаторы и tick берутся из
  `getStatusMechanics()`, а не копируются разными renderers.
- [ ] Пользовательский статус хранит собственное ограниченное описание, но не
  подменяет системный статус с тем же ключом.

### 4.2. Авторитетные часы комнаты

```js
room.worldClock = {
  calendarId: "zargota-default",
  totalMinutes: 0,
  day: 1,
  month: 1,
  year: 1,
  revision: 0,
  updatedAt: 0,
  updatedBy: "",
  lastOperationId: ""
}
```

- [ ] Источником истины является `totalMinutes`; остальные поля вычисляются по
  выбранному календарю.
- [ ] Время может менять только ГМ отдельной transaction-operation.
- [ ] Игроки получают только read-only snapshot.
- [ ] Повтор операции с тем же `operationId` ничего не прибавляет второй раз.
- [ ] Время не откатывается после reconnect или старого локального snapshot.
- [ ] Локальный `globalTime` мигрируется только один раз или остаётся legacy
  fallback вне комнаты; он не перезаписывает `room.worldClock`.

### 4.3. Слоты оружия

Целевая модель:

```js
slot: "mainHand" // mainHand | offHand
handsRequired: 1 // 1 | 2
```

- [ ] `mainHand` — основное оружие.
- [ ] `offHand` — второе лёгкое оружие или щит.
- [ ] Двуручный предмет занимает обе руки, но существует в массиве один раз.
- [ ] Нельзя одновременно надеть двуручное оружие и предмет в offhand.
- [ ] Старый `slot: "weapon"` безопасно трактуется как `mainHand`.
- [ ] Старые щиты и предметы с неоднозначным типом не мигрировать молча: сначала
  классифицировать, иначе оставить в рюкзаке с понятным уведомлением.
- [ ] Боевой `weaponProfiles` видит оба подходящих оружия и не создаёт дубликаты.

Реализовано 29 июля 2026:

- network normalization больше не превращает `hours` и `days` в `rounds` и не
  сбрасывает `remaining` при изменении stacks/visibility;
- для обратной совместимости положительная длительность без `unit` читается как
  раунды, а `manual` не хранит ложное числовое значение;
- конец боевого хода уменьшает только `rounds`; часы и дни ждут отдельной
  авторитетной операции `worldClock`;
- при добавлении состояния ГМ сначала видит компактную форму длительности,
  видимости и stacks; активное состояние можно перенастроить кнопкой с песочными
  часами;
- запись по-прежнему проходит одной Firebase `update()` вместе с revision, но
  отдельный `effectId` ещё не введён, поэтому соответствующий пункт оставлен
  открытым;
- контрактные тесты покрывают legacy, rounds, hours, days, manual и запрет
  уменьшения мировых длительностей боевым ходом.
