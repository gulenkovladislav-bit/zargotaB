- [~] **ZT-001 — Firebase запрещает приватные доставки игроку.**
  В Console игрока: `permission_denied` на
  `/privateDeliveries/<roomCode>/<clientId>`. Проверить матрицу прав ГМ/игрок,
  подписку игрока только на собственную ветку и Firebase Rules Emulator.

- [~] **ZT-002 — игроку запрещена запись liveMeasurements.**
  Повторяется `permission_denied` на
  `/rooms/<roomCode>/liveMeasurements/<clientId>` при открытии сумки,
  переключении вкладок и кликах по портрету. Определить, нужна ли запись игрока
  вообще; если нужна — разрешить только собственный `clientId` и валидную форму,

  Доказательства: [14](test-evidence/2026-07-30-stage-1/14-player-character-list-six.png),
  [15](test-evidence/2026-07-30-stage-1/15-bag-live-measurement-denied.png),

  [21](test-evidence/2026-07-30-stage-1/21-bag-tabs-console-errors.png).

- [~] **ZT-003 — пользовательские портреты превращаются в несуществующие URL.**
  В Firebase/листе сохраняются пути наподобие

### Решения по архитектуре перед реализацией

#### Единый каталог предметов

Принять раздел **«Товары» единственным каноническим каталогом предметов**.
Отдельную оружейную Арены после миграции удалить.

- Каталог хранит шаблон предмета: название, категория, совместимые слоты,
  изображение/asset key, формулу урона, броню, свойства и описание.
- Инвентарь героя хранит экземпляр: `instanceId`, `itemId`, количество,
  состояние, заряды, персональные изменения и текущий слот.
- Арена читает экипировку героя и создаёт боевые действия из тех же экземпляров.
- Редактор снаряжения выбирает предметы из «Товаров» и использует тот же
  браузер сгенерированных изображений, что обычный редактор.
- Перед миграцией сделать backup обоих старых хранилищ; неизвестные предметы
  преобразовать в пользовательские товары, ничего не удалять молча.

#### Герои кампании и обновления от ГМ

- Пять основных героев — опубликованные шаблоны кампании, а не копии,
  которые при старте перетирают локальные листы.
- Игрок может создать локального героя и отправить ГМ заявку на добавление.
- После принятия герой получает campaign ID и становится доступен в комнате.
- ГМ отправляет игроку field-level patch с ревизией и кратким описанием.
- Игрок видит diff и принимает/отклоняет обновление.
- При конфликте сохраняются обе версии; полный лист автоматически не
  перезаписывается.

#### Заметки, журнал и древо связей

- Поля главного листа остаются источником личной информации героя.
- «Передать в журнал» создаёт запись с `sourceCharacterId` и ссылкой на исходное
  поле, а не переносит текст разрушительно.
- Обновление древа связей отправляется тем же механизмом patch/update.
- В сессии древо открывается компактным popup по отдельной кнопке.

1. **Сеть и изображения:** ZT-001–ZT-004. Исправить права адресно, прекратить
   запрещённые записи, восстановить передачу портретов и asset key предметов.
   Затем повторить вход, reload, открытие сумки и Console на двух клиентах.
2. **Стабильность сессии:** ZT-010, ZT-013–ZT-015. Один toggle сумки, одно
   событие анимации HP, финальный save/outbox при выходе, без полного
   перерендера чата.
3. **Единые предметы:** ZT-005–ZT-006. Сначала backup и миграционный тест,
   затем переключить Арену на каталог «Товаров» и проверить
   надеть → снять → надеть повторно на двух клиентах.
4. **Герои и контент:** ZT-007–ZT-012. Заявка нового героя, patch-обновления,
   связь заметок/древа с журналом, публичный профиль союзника и задания.
5. **Визуал и настройки:** ZT-016–ZT-023. После стабилизации данных, чтобы
   последующий сетевой рефакторинг не уничтожил визуальную работу.
6. Повторить разделы 1–3. Если Console чистая и данные не откатываются —
   продолжить основной чек-лист с раздела 4.

- [ ] Золотой Листопад занимает дни 181–270.
- [ ] Серебряный Мороз занимает дни 271–360.
- [ ] Переходы между сезонами и годами работают.
- [ ] Каждый пятый день помечен выходным.
- [ ] Дата ЛВК написана без склеенных слов и чисел.
- [ ] Иконка сезона соответствует названию.
- [ ] Изменение времени корректно уменьшает часовые и дневные статусы.

# 13. Бой и передвижение

- [ ] ГМ начинает бой с выбранными участниками.
- [ ] Если нужна инициатива, бросок не выполняется автоматически.
- [ ] Появляется окно инициативы с кубиком и объяснением.
- [ ] Очередь одинакова у ГМ и игрока.
- [ ] Игрок может завершить свой ход.
- [ ] Игрок не может завершить чужой ход.
- [ ] Двойной клик не пропускает участника.
- [ ] Reconnect не выполняет переход хода повторно.
- [ ] Активный герой может двигаться.
- [ ] Неактивный герой не может потратить чужое движение.
- [ ] Дальность движения соответствует скорости.
- [ ] Запрещающий движение статус блокирует действие.
- [ ] Выбор точки можно отменить без расхода движения.
- [ ] Положение жетона не прыгает после reconnect.

## Атака, урон и лечение

- [ ] Обычное и тяжёлое оружие попадает через Силу или Ловкость.
- [ ] Урон обычного и тяжёлого оружия получает бонус Силы.
- [ ] Лёгкое оружие использует Ловкость для попадания и урона.
- [ ] Дальнобойное оружие использует Ловкость только для попадания.
- [ ] Успешная атака наносит не нулевой урон.
- [ ] Урон работает по существам, героям и другим игрокам.
- [ ] Крит удваивает только нужные кубы.
- [ ] Сопротивление, уязвимость и иммунитет работают.
- [ ] Temp HP поглощает урон первым.
- [ ] Лечение не превышает максимум.
- [ ] Урон и лечение одинаковы в листе, жетоне и бою.

# 14. Ноль HP и смерть

- [ ] Оружие может опустить героя до 0 HP.
- [ ] Заклинание может опустить героя до 0 HP.
- [ ] Периодический урон может опустить героя до 0 HP.
- [ ] ГМ может опустить героя до 0 HP.
- [ ] При 0 HP герой не удаляется из боя и сцены.
- [ ] Перед завершением хода появляется окно «Борьба за жизнь».
- [ ] В окне есть объяснение, иконка и d20.
- [ ] Автоматического броска нет.
- [ ] Пока кубик не нажат, ход не продолжается.
- [ ] Результат 1–9 даёт одну неудачу.
- [ ] Результат 10–20 даёт один успех.
- [ ] Натуральная 1 даёт две неудачи.
- [ ] Натуральная 20 даёт два успеха.
- [ ] За один раунд нельзя бросить дважды.
- [ ] Прогресс видят ГМ и игрок.
- [ ] Четыре успеха стабилизируют героя.
- [ ] Четыре неудачи переводят героя в состояние смерти.
- [ ] Мёртвый герой не может двигаться, атаковать или кастовать.
- [ ] Жетон мёртвого героя остаётся на сцене с понятной отметкой.
- [ ] Лечение до окончательной смерти возвращает героя по правилу.
- [ ] Возвращение после окончательной смерти требует решения ГМ.
- [ ] Reload сохраняет успехи, неудачи и состояние.

# 17. Offline, несколько вкладок и права

- [ ] HP, предмет, статус, журнал, заряд и ход не откатываются.
- [ ] Подтверждённые операции исчезают из очереди.
- [ ] Вторая вкладка показывает предупреждение.
- [ ] Только активная вкладка отправляет операции.
- [ ] Передача управления делает старую вкладку read-only.
- [ ] Две вкладки не создают второго участника.
- [ ] Вторая вкладка ГМ не дублирует выдачу или эффект.
- [ ] Игрок меняет только своего героя.

## Как прислать мне визуальную проблему

Скопируй этот короткий блок и приложи скриншот:

```text
Где: экран → вкладка → блок
Роль и разрешение:
Что сейчас плохо:
Как должно выглядеть:
Что нельзя двигать или менять:
Что можно менять:
Скролл: запрещён / только внутри блока / допустим
Нужна анимация:
Нужно новое изображение или текстура:
Когда считаем готовым:
```

Пример:

```text
Где: Сумка → Вещи → две руки
Роль и разрешение: игрок, 1920×1080
Что сейчас плохо: подписи ломаются, ячейки не выглядят одной группой.
Как должно выглядеть: две равные симметричные ячейки.
Что нельзя двигать или менять: внешнюю рамку, ширину колонки и верхние вкладки.
Что можно менять: внутреннюю сетку, отступы, текст и пустое состояние.
Скролл: запрещён.
Нужна анимация: мягкий hover без изменения размера.
Нужно новое изображение или текстура: нет.
Когда считаем готовым: текст читается, ячейки равны, соседи не двигаются.
```

Если нужно сгенерировать изображение, допиши:

```text
Что изображено:
Стиль и палитра:
Фон: прозрачный или полный
Формат и пропорции:
Что оставить пустым под интерфейс:
Что строго не добавлять:
Сколько вариантов:
```

Для рамок, свечения, сетки и hover новое изображение обычно не нужно. Генерация
нужна для пергамента, атмосферного фона, арта предмета, заклинания, места, NPC
или прозрачного слоя льда/огня.
